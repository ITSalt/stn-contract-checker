> Пишется один раз, правится редко. Текущее состояние — в `status.md`.

## Цель и условие завершения

Сдать тестовое задание Product Owner (Semantic TextNavigator): работающий локальный прототип
проверки условий договоров поставки для специалиста по закупкам, с проверяемыми основаниями,
README и запиской, в бюджете 4 часа (D-3, A-3: до 12:40Z 2026-10-30).

Условие завершения: WP-APP-01…03 смержены в `main` ITSalt/stn-contract-checker; в чистом клоне
`npm ci && npm test && npm run build` зелёные; живая проверка на `documents/` даёт эталон
(STN-101: 1 380 000 ₽ и 30.04.2026, изменено `02_amendment_signed.txt`, проект — отдельно;
STN-102: 840 000 ₽, 20.03.2026, письмо о переносе на 27.03.2026 — несогласованное; STN-103:
сумма «нет данных», 30.04.2026; вопрос 4 → STN-102 с несогласованным изменением срока); README
содержит все пункты «Что прислать» и фактические затраты. Когда условие выполнено, программа закрывается
(`close`); следующая цель — новая программа.

## Объём

1. Движок разбора TXT на правилах (A-1): абзацы, классификация документа по тексту, извлечение
   номера, поставщика, суммы, срока с цитатой, применение изменений по дате проверки (A-2, D-7).
2. Интерфейс на дизайн-системе <проект-источник> (D-5): загрузка, таблица, основание с переходом к
   абзацу, сведения для проверки, фильтры и 4 кнопки вопросов (D-6), редактируемая дата (D-7).
3. README, записка PO, отчёт о вайбкодинге, проверка запуска в чистом клоне.

### Не входит

- LLM внутри приложения (A-1 — обоснование в README), бэкенд (D-4)
- OCR, PDF/DOCX, промышленное развёртывание, свободный чат
- извлечение неустойки — это задача демо; движок лишь готов к добавлению поля одним файлом

## Проверка в браузере и протокол снимков (D-9)

Сценарий Playwright `e2e/scenario.spec.ts` (`npm run e2e:shots`, WP-APP-02) проходит путь закупщика
и снимает 10 экранов с постоянными именами. Оркестратор прогоняет его в одноразовом клоне на SHA
и складывает снимки в `reports/screenshots/<NN>-<метка>-<sha7>/`, строка — в
`reports/screenshots/INDEX.md`. Точки съёмки:

| № | Когда | Что показывает |
|---|-------|----------------|
| 00 | сейчас | исходный каркас (стартовая страница Vite) — «что было в начале» |
| 01… | каждый ревью-раунд WP-APP-02 | первая версия UI и каждая доработка по REVISE |
| следующий | после слияния WP-APP-02 и WP-APP-03 | версия в `main` |
| финал | чистый клон перед сдачей | версия для клиента |
| демо | после изменения на встрече (например, неустойка) | если будет |
