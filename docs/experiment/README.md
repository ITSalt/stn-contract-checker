# Материалы эксперимента: как прототип делался с ИИ

Здесь — следы процесса, а не код продукта: план, решения, отчёты ревью, приёмка тремя «клиентами» и
снимки каждой версии интерфейса. Всё собрано из рабочего пространства оркестратора; пути заменены на
относительные, упоминания внутреннего проекта, откуда взята дизайн-система, обезличены.

## Как была устроена работа

- **Инструмент:** Claude Code. Одна сессия-оркестратор планировала, писала пакеты работ с критериями
  приёмки, раздавала их сессиям-исполнителям (движок и интерфейс, дизайн-система, записка, позже —
  отдельный поток интерфейса), проверяла каждый PR и сливала принятые.
- **Проверка:** каждый PR проверял независимый агент-рецензент в одноразовом клоне — свои варианты
  документов, мутации кода, прогон тестов. Пересдачи сверял оркестратор по диффу ревизии.
- **Владелец** (человек) принимал продуктовые решения на развилках: они записаны в
  [process/decisions.md](process/decisions.md) (D-n — решение, A-n — допущение).

## Динамика версий (снимки)

| № | Версия | Что видно |
|---|--------|-----------|
| 00 | каркас | стартовая страница Vite, ни одной функции |
| 01 | первая сдача интерфейса | рабочий экран закупщика |
| 02 | интерфейс после ревью | «нет данных: сумма» вместо «ок», переход к абзацу, верные ярлыки |
| 03 | первая версия для клиента | то, что прошло приёмку тремя клиентами в первый раз |
| 04 | финальная версия | после исправлений по приёмке, проверено на чистой машине и агентом клиента |

Сравнивать удобно одноимённые кадры разных версий, например `02-uploaded-table.png` и
`03-evidence-stn101-delivery.png`.
